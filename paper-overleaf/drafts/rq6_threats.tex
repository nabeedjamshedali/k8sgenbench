\textbf{Guided generation and repair (RQ6).} The guided prompt and the gate were developed by the authors, who knew why the development configurations had failed. The split into development and test projects limits how much of that knowledge reaches the test results, but it cannot remove it: the rules encode failure mechanisms, and a mechanism seen on a development project may recur on a test project for the same reason. We kept every rule free of project names, images and values, and we report the development results of each prompt version. Development used one sample per model and project for each version, so a difference between versions on a single project can be sampling variation; we do not attribute one to a rule unless the configuration shows the rule's effect directly (for example, an explicitly set dependency address). The listening-port check (vii) was added after the first development round, so it applies to the second round and to the test runs only. While developing the loop we also found that a configuration placed in \texttt{kube-system} received the logs of the cluster's own components as feedback, including names of other projects; we restricted feedback to objects the configuration created and re-ran the affected rounds before the prompt was frozen. One smoke check was corrected during the test phase. For Wordsmith, the check that the database was seeded first required exactly the 18 nouns of the upstream seed script, but that script is not part of the documentation the models receive, so no generated configuration could pass it; four configurations whose application served words correctly failed only on this count. Before any test results were analysed, we audited all smoke checks of all projects for values that cannot be derived from the model's input and found no other. We changed this check to require a seeded table with at least one row and re-scored every Wordsmith configuration, from every model and condition, from the stored check output. The change turned four Wordsmith configurations into passes (two from the production baseline, two guided) and changed no other result; the strict outcome is kept alongside the corrected one in the released data. Access limits shape the repair results. Qwen's free tier rejects a repair request once it contains the documentation, the previous configuration and the feedback for a large project, so for \TODO{TODO-FINAL: n} configurations the loop stopped before a repair could be sent; we report these as stopped by the provider, not as failed repairs. Gemini calls that timed out or were refused by the provider were retried later and nothing from a failed call was kept. Claude's repair turns were produced by a fresh subagent that read the whole conversation as one prompt, not by a continuing chat session.
