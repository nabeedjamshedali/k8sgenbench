\textbf{Guided generation and repair (RQ6).} The guided prompt and the gate were developed by the authors, who knew why the development configurations had failed. The split into development and test projects limits how much of that knowledge reaches the test results, but it cannot remove it: the rules encode failure mechanisms, and a mechanism seen on a development project may recur on a test project for the same reason. We kept every rule free of project names, images and values, and we report the development results of each prompt version. Development used one sample per model and project for each version, so a difference between versions on a single project can be sampling variation; we do not attribute one to a rule unless the configuration shows the rule's effect directly (for example, an explicitly set dependency address). The listening-port check (vii) was added after the first development round, so it applies to the second round and to the test runs only. While developing the loop we also found that a configuration placed in \texttt{kube-system} received the logs of the cluster's own components as feedback, including names of other projects; we restricted feedback to objects the configuration created and re-ran the affected rounds before the prompt was frozen. One test project's input was corrected during the test phase. Wordsmith's Compose file mounts a directory with a database seed script into a stock Postgres image, and the application serves nothing without it; the documentation bundle omitted this script, although our fact sheet cited it and our own bundle rule requires every cited file to be in the bundle (the n8n bundle includes its mounted init script for the same reason). A model could therefore pass Wordsmith only by recalling the upstream repository. We checked every project for a file that the Compose setup deploys, that the application needs to work, and that the bundle lacks, and found no other. We added the script unchanged, kept the original smoke check, archived every Wordsmith generation made with the first bundle, and generated and evaluated Wordsmith again for all models and conditions; the archived runs are released but not analysed. Access limits shape the repair results. Qwen's free tier rejects a repair request once it contains the documentation, the previous configuration and the feedback for a large project, so for \TODO{TODO-FINAL: n} configurations the loop stopped before a repair could be sent; we report these as stopped by the provider, not as failed repairs. Gemini calls that timed out or were refused by the provider were retried later and nothing from a failed call was kept. Claude's repair turns were produced by a fresh subagent that read the whole conversation as one prompt, not by a continuing chat session.
