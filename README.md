# K8sGenBench — replication package

Replication package for *Reliability and Security Analysis of LLM-Generated Kubernetes Configurations: A
Project-Matched Comparison of Human-Written and Multi-LLM Manifests* (N. Ali, T. Hussain; NED University of
Engineering and Technology).

It contains everything needed to regenerate every number, table and figure in the paper from the stored model outputs,
and to re-run generation and evaluation from scratch.

## Layout

| Path | Contents |
|---|---|
| `datasets/Pxx_<project>/` | One folder per project. `docs_bundle/` holds the only input a model sees: the README, Dockerfile(s) and Compose file at a pinned commit, with Kubernetes-specific content redacted. `human/` holds the manifests the project ships. `requirements.py` holds the D4 checks, `smoke.json` the D5 smoke test and D6 target, and `image_aliases.json` the D5 alias rule (where present). `internal/` holds the fact sheet, provenance, redaction log and metadata; none of it is shown to a model. |
| `datasets/common/` | `redact.py` (bundle redaction), `reqlib.py` (D4 helpers), `smoke.py` (D5 smoke test and client placement). |
| `generation/` | `models.yaml` (model IDs, parameters, system prompt) and `generate.py` (API generation, one call per sample). `relay.py` handles the web-chat models, and `claude_records.py` records the Claude subagent runs. |
| `generation/outputs/<model>/<project>/<variant>/s<k>/` | Every generation: `request.json`, `response_raw.json` (the raw provider response), `manifest.yaml` (the extracted YAML) and `extraction.json`. |
| `generation/relay/` | The exact prompts pasted into web chats (`prompts/`), the replies as received (`inbox/`) and the relay instructions. |
| `evaluation/` | `eval_runner.py` runs one configuration through D1–D6, using `d2d3.py` (static scanners) and `d5d6.py` (deploy, smoke, faults). `r8_batch.sh` drives the full run. `stats.py`, `figures.py` and `tables.py` are the analysis. |
| `evaluation/results/` | One JSON record per configuration, plus `raw/<config>/` with every scanner's untouched output. |
| `evaluation/analysis/` | Generated: `report.md` (all tests), `configs.csv`, summaries, `contamination.csv` and `rq2_rahman.csv`. |
| `evaluation/mirror_ledger.json` | For every image reference: whether it was pullable as written, and what D5 served. |
| `tools/` | `versions.lock` (every pinned tool and image version), `install_tools.py`, `kind-cluster.yaml`, `setup_cluster.py`, `mem_guard.sh`, and `scanner-artifacts/` (offline Kubescape artifacts, Trivy checks and the kubeconform schema cache). |
| `paper/` | LaTeX sources. `sections/` holds the text, while `tables/` and `figures/` are generated by the scripts below. |
| `demo/` | `app.py`: a local web page that shows a project's human and generated configurations side by side, re-runs the pipeline live and prints a comparison report (see `demo/README.md`). |

## Requirements

- Docker (pinned engine version in `tools/versions.lock`) with about 14 GB of memory available to it.
- Python 3.14 with `pyyaml`, `httpx`, `numpy`, `pandas`, `scipy` and `matplotlib`.
- The pinned tool binaries: `python tools/install_tools.py --locked`.

## Reproduce the paper's numbers from the stored results (no cluster needed)

```
python evaluation/stats.py      # evaluation/analysis/report.md and the CSVs
python evaluation/figures.py    # paper/figures/*.pdf
python evaluation/tables.py     # paper/tables/*.tex
python paper/build_overleaf.py  # paper/overleaf_files/ (single main.tex plus assets)
```

## Re-run the evaluation (D1–D6)

```
python tools/setup_cluster.py --recreate      # kind, 1 control plane + 3 workers, registry mirror, open-files cap
bash tools/mem_guard.sh 10000 &               # optional safety net: deletes the cluster if the nodes exceed 10 GB
bash evaluation/r8_batch.sh claude deepseek gemini qwen gpt
```

- A configuration whose result JSON already exists is skipped, so the batch can be stopped and resumed. `touch evaluation/.r8_stop` stops it between configurations.
- One configuration at a time: `cd evaluation && python eval_runner.py <model> <project> <variant> <k> --runtime`.
- A configuration that fails for an infrastructure reason (for example, a transient image-pull failure) writes no result and is retried. It is never scored.

## Re-run generation

- **API models:** `python generation/generate.py <model> <project> <neutral|production> <k>`. Keys are read from `.env` (`GEMINI_API_KEY`, `GROQ_API_KEY`). The `.env` file is not part of this package.
- **Web-chat models:** follow `generation/relay/HOW_TO_RELAY.md`, then run `python generation/relay.py import`.
- Model outputs vary across runs and model versions. The stored outputs are the ones the paper analyses, and Threats to Validity lists every deviation from the planned protocol.

## Notes

- Image tags are resolved when the registry mirror is populated, so an unpinned tag is measured as it resolved at evaluation time (November 2026). See `evaluation/mirror_ledger.json`.
- Every correction made to the evaluation pipeline during the study is listed in Appendix A of the paper.
