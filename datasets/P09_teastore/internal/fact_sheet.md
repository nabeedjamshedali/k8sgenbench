# TeaStore

## Purpose
A micro-service reference and test application for benchmarks and tests. It emulates a basic web store for automatically generated, fictitious teas, tea accessories and supplies. It consists of five services (WebUI, Authentication, Recommender, Persistence Provider, Image Provider), a service registry and a MariaDB database. The services communicate over REST and find each other through the registry.

## Components

| Component | Image | Role |
|---|---|---|
| registry | `descartesresearch/teastore-registry` | Service registry. Every service registers its address here and looks up the addresses of the services it calls |
| db | `descartesresearch/teastore-db` | Pre-configured MariaDB database used by the persistence service |
| persistence | `descartesresearch/teastore-persistence` | Persistence Provider: REST access to the store data in the database; generates the store data when the database is empty |
| auth | `descartesresearch/teastore-auth` | Authentication service: login, logout, session checks, shopping cart and order placement |
| image | `descartesresearch/teastore-image` | Image Provider: generates and serves product and web images |
| recommender | `descartesresearch/teastore-recommender` | Recommender: product recommendations, trained on the order data |
| webui | `descartesresearch/teastore-webui` | Web front end of the store (Java servlets/JSP) |

All components except db are Java web applications running in Tomcat. Each listens on HTTP port 8080 and serves its application under the context path `/tools.descartes.teastore.<service>/` (for example `/tools.descartes.teastore.webui/`).

## Service discovery
- The services do not use fixed hostnames for each other. Each service (persistence, auth, image, recommender, webui) registers itself with the registry under its service name, together with an address `host:port`, and sends heartbeats. The other services ask the registry for the addresses of a service and call it there.
- Each service is told where the registry is with `REGISTRY_HOST` (hostname or IP of the registry) and `REGISTRY_PORT` (default `8080`). `REGISTRY_HOST` defaults to `127.0.0.1` in the image, so it must be set.
- The address a service registers is `HOST_NAME:SERVICE_PORT`:
  - `HOST_NAME`: the hostname or IP under which the other services can reach this instance. If unset, the OS-provided hostname is used.
  - Alternatively `USE_POD_IP=true`: the service registers its own (pod or container) IP and ignores `HOST_NAME`. The project documentation recommends this alternative to `HOST_NAME` when deploying in Kubernetes.
  - `SERVICE_PORT` (default `8080`): the port the service registers. It must be the port at which the other services reach the instance.
- The registered address must therefore be resolvable and reachable from every other TeaStore service.
- Startup order does not matter: every service retries connecting to the services it needs until they are available.

## Component details

### registry
- Listens on HTTP port 8080. Registry REST API under `/tools.descartes.teastore.registry/rest/services/`.
- Does not register with itself; it does not need `REGISTRY_HOST`.

### db
- Listens on port 3306 (MariaDB 10.4).
- The image is pre-configured: it creates database `teadb` with user `teauser` and password `teapassword` at first start. No environment variables are needed.
- The database content is generated by the persistence service at startup when the database is empty. The project's own Docker setups run the database without a volume.

### persistence
- Listens on HTTP port 8080.
- Environment variables: `REGISTRY_HOST`, `REGISTRY_PORT`, `HOST_NAME` (or `USE_POD_IP`), `SERVICE_PORT` as described above, and
  - `DB_HOST` (required): hostname or IP of the database. The image default is `127.0.0.1`.
  - `DB_PORT`: port of the database, default `3306`.
- Connects to database `teadb` as user `teauser` with password `teapassword`. These credentials are fixed in the application code.
- Waits until the database is reachable, generates the store data if the database is empty, and only then registers with the registry.
- Health endpoint: `GET /tools.descartes.teastore.persistence/rest/generatedb/finished` returns 200 once data generation has finished.

### auth
- Listens on HTTP port 8080.
- Environment variables: `REGISTRY_HOST`, `REGISTRY_PORT`, `HOST_NAME` (or `USE_POD_IP`), `SERVICE_PORT`.
- Uses the persistence service (found through the registry).
- Health endpoint: `GET /tools.descartes.teastore.auth/rest/ready/isready` returns 200.

### image
- Listens on HTTP port 8080.
- Environment variables: `REGISTRY_HOST`, `REGISTRY_PORT`, `HOST_NAME` (or `USE_POD_IP`), `SERVICE_PORT`.
- Uses the persistence service (found through the registry).
- Health endpoint: `GET /tools.descartes.teastore.image/rest/image/finished` returns 200 once image generation has finished.

### recommender
- Listens on HTTP port 8080.
- Environment variables: `REGISTRY_HOST`, `REGISTRY_PORT`, `HOST_NAME` (or `USE_POD_IP`), `SERVICE_PORT`.
- Optional: `RECOMMENDER_ALGORITHM` (`Popularity`, `SlopeOne`, `PreprocessedSlopeOne` or `OrderBased`; default `SlopeOne`) and `RECOMMENDER_RETRAIN_LOOP_TIME` (retraining interval in ms; default `0`, disabled).
- Uses the persistence service (found through the registry).
- Health endpoint: `GET /tools.descartes.teastore.recommender/rest/train/isready` returns 200 once training has finished.

### webui
- Listens on HTTP port 8080. The store is served at `/tools.descartes.teastore.webui/`; `/` redirects there.
- Environment variables: `REGISTRY_HOST`, `REGISTRY_PORT`, `HOST_NAME` (or `USE_POD_IP`), `SERVICE_PORT`.
- Optional: `PROXY_NAME` and `PROXY_PORT`, only needed if a front-end load balancer proxy is placed in front of the WebUI.
- Uses persistence, auth, image and recommender (found through the registry).
- Status page `GET /tools.descartes.teastore.webui/status` lists the registered instances of every service and whether data generation has finished.
- Health endpoint: `GET /tools.descartes.teastore.webui/rest/ready/isready` returns 200.

## Dependencies
- persistence, auth, image, recommender and webui depend on registry.
- persistence depends on db.
- auth, image and recommender depend on persistence.
- webui depends on persistence, auth, image and recommender.

## External access
- The WebUI (port 8080) must be reachable from outside the cluster; users open the store at `/tools.descartes.teastore.webui/`.
